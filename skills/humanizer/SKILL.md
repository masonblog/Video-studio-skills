# Humanizer — 去 AI 化 + 口播叙事化润色

把"写出来的文字"改成"说出来的话"。本技能覆盖两个互补的润色维度：

1. **去 AI 化**：逐条扫描 29 项 AI 写作痕迹（宣传腔、高频词、模板化结构、翻译腔等），清除"机器味"。
2. **口播叙事化**：面向 TTS 配音和听觉接收改写——控制句长、留出气口、消除听觉歧义，让脚本读出来像朋友聊天。

为 video-studio 管线 Stage 3 定制（输入 `script-draft.md`，输出 `script-final.md` + `edit-report.md`），也可独立用于任何口播文稿的润色。

## When to use

- video-studio 管线 Stage 3：Editor 对脚本草稿做去 AI 化润色
- 任何将被 TTS 朗读或真人口播的文稿（播客稿、解说词、演讲稿）
- 用户要求"去 AI 味""更像人话""口语化"的文本改写

## 总原则

- **好文字读出来不像文字，像说话。** 默读时脑中浮现机器人，就是失败。
- **砍，砍，砍。** 第一反应永远是：这句删掉会损失信息吗？不会就删。
- **具体打败抽象。** "提升 37%" > "显著提升" > "提升"。
- **短句打败长句。** 逗号的正确数量是"刚好够"，通常比你想的少一个。
- **只改表达，不改事实。** 数字、引用来源、论文结论一个都不能动；拿不准的标注出来，不要"顺手修正"。

## 工作流：三遍法

### 第一遍：AI 痕迹扫描（去 AI 化）

逐条对照 **[references/ai-trace-checklist.md](references/ai-trace-checklist.md)**（29 条完整清单，含逐条反例与改法），记录 `行号 + 条目编号 + 原文 + 改法`。五大类速览：

| 类别 | 编号 | 典型痕迹 |
|------|------|----------|
| 内容类 | #1-6 | 重要性强调、宣传腔、浅层升华分析、模糊归因、"挑战与未来"模板、万能总结 |
| 语言类 | #7-13 | 高频 AI 词汇、"是"回避症、三件套排比、同义词轮换、名词化堆叠、万能形容词、机械过渡词 |
| 风格类 | #14-19 | 破折号滥用、粗体滥用、列表化倾向、emoji、标题党小标题、引号滥用 |
| 沟通类 | #20-24 | 对话伪影、AI 自指声明、谄媚语气、过度对冲、免责声明强迫症 |
| 中文专项 | #25-29 | 翻译腔句式、成语堆砌、正式动作词、书面连词、首尾呼应金句 |

### 第二遍：口播叙事化改写

面向"耳朵"而非"眼睛"逐句改写：

- **句长 ≤ 25 字**：一口气能读完。超长句拆短，从句改成两句话。
- **听觉歧义排查**：同音易混词（"权利/权力"、"启示/启事"）换说法；生僻字、专业缩写首次出现时口头展开（"VTT，就是字幕时间轴文件"）。
- **数字口语化**：精确度不承载论点的数字改约数（"37.42%" → "三成七左右"）；承载论点的精确数字保留并放慢节奏给足强调。
- **口语连接**：段落衔接用"那""你看""说白了""但你猜怎么着"，替代"然而""此外""综上所述"。
- **人称直接化**："我查了一下" > "我们经过调研发现"；多用"你"制造对话感。
- **强调靠语序和停顿**，不靠粗体："注意……接下来这一步，才是关键。"
- **气口与段落结构**：每 2-3 句留一个自然停顿点（句号断开）；保持段落间空行——下游 Narrator 依赖 `\n\n`（约 500ms）/`\n\n\n`（约 800ms）生成 TTS 停顿（见 video-studio-orchestrator 的 `references/tts-first-narration-guide.md`）。润色时不要合并 Writer 留出的段落空行。

**职责边界**：口播叙事化只做"表达层"改写，不重构叙事。场景顺序、故事节拍、Hook 设计是 Writer 的职责——发现结构性问题（跑题、叙事弧线断裂、场景碎片化）应上报 Director 判定是否退回 Stage 2，而不是自己动手重写。

### 第三遍：朗读测试（Read-Aloud Test）

模拟出声朗读全文，逐项检查：

- [ ] 有没有一口气读不完的句子？（拆短）
- [ ] 有没有读起来绕口的字词组合？（换词）
- [ ] 听众只靠耳朵能跟上吗？有没有"看得懂听不懂"的表达？
- [ ] 段落节奏有起伏吗？连续 5 句以上同样长度的句子会催眠。
- [ ] 每个场景的第一句能拉住注意力吗？

## 🔴 红线（不可触碰）

1. **VAS 视觉标签**：脚本中所有 `[画面:...]`、`[图表:...]`、`[动画:...]`、`[转场:...]`、`[REACT_ANIM_CUE:...]` 标签及其缩进元素描述和内部参数（`entrance=`、`dur=Nf` 等）是下游 Renderer 的直接渲染依据。**严禁修改、移动或删除**。润色范围仅限旁白文本。
2. **事实与引用**：数字、数据出处、论文名、人名一律保留。去 AI 化去的是"表达的机器味"，不是内容。
3. **场景结构**：`## {场景名} — {概括}` 的 Markdown section 结构和场景名（Hook、Act1_A……）保持不变——Narrator 的 timing.json 按场景名对齐。

## 输出格式

交付润色后全文 + 修改报告。报告每条修改标注清单编号和原因——让 Writer 理解为什么改，而不是觉得被冒犯；写得好的段落也要指出来。

```markdown
## 修改报告

### AI 痕迹修复
- [#1 重要性强调] Line 12 "标志着关键的转折点" → 删除（这是 2022 年的一篇论文，仅此而已）
- [#7 高频词] Line 45 "至关重要" → "这里真正需要看懂的是..."
- [#14 破折号] Line 78-80 → 替换为逗号

### 口播叙事化
- Line 23 "在某种程度上" → 删除（弱化语气，反而显得不自信）[#25 翻译腔]
- Line 56 "进行测试" → "跑一遍测试" [#27 正式动作词]
- Line 102 "算法复杂度呈指数级增长" → "复杂度爆炸式增长"（更口语）

### 朗读测试
- Line 89 原句 28 字过长 → 拆为两句

### 保留与好评
- Line 30-35 Hook 段落的类比很妙，未改动
- 全部 VAS 标签原样保留（共 14 处）

### 统计
AI 痕迹修复 N 处 / 口播化调整 N 处 / 朗读优化 N 处 / VAS 标签 N 处（0 改动）
```
